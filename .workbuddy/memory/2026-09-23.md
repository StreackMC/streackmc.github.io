## 追加：loop-cards 组件重构（提交 `c47c68a`）

组件零引用，用户明确可以放心重构。规格（拼写修正：`continuous` 而非 `contiuous`）：

- `data-orientation`：horizontal / vertical / reverted-horizontal / reverted-vertical
- `data-type`：`continuous`（无缝滚动，speed = 速度倍率）/ `pausing`（每张停顿片刻，speed = 停顿秒数）
- `data-controller-type`：`step`（两个玻璃按钮，箭头随轮播方向变）/ `step-pause`（多一个暂停按钮）/
  `progress`（胶囊进度条 + 暂停按钮；当前卡片的点展开为进度条，满了切下一张）
- `data-controller-pos`：left|center|right × top|bottom（用户补充，六方位）
- `data-controller-overlap`：用户补充；false（缺省）控制器参与布局把容器撑开，true 叠在卡片上

### 用户拍板的两个关键语义
- **continuous 下任何控制器都只渲染暂停/继续按钮** —— 连续滚动没有「当前卡片」概念，进度条无意义
- **pausing 的 speed 单位是秒**，支持小数、精度到毫秒、超出位数直接舍弃（`secondsToMs` 用 `Math.floor(n*1000)`）

### 实现要点
- `ORIENTATIONS` 把「轴 + 位移符号」抽象出来，位移 / 回绕 / 步长统一按轴计算
  （正向从 offset 0 向 -span 走，反向从 -span 向 0 走，视觉上都以第一张起始）
- 结构改为 `容器 > 视口(overflow:hidden) > 轨道`，控制器与视口**平级**
  → 按钮不再被 `pointer-events:none` 影响，可点
- 停顿模式用 CSS transition 走步进动画（`MOVE_MS` 单一常量，JS 写入 transition 时长），
  停留计时与进度条由 rAF 驱动；`advance()` 由自动步进与 step 按钮共用
- 分支决策抽成纯函数 `resolveController(isPausing, ctrlType)` → 自检能覆盖全部组合
- 样式从 `frame/framework.css` 移出为 `component/loop-cards.css`，由组件用
  `new URL('./loop-cards.css', import.meta.url)` 按需注入（首次真正「组件自带样式」）

### 验证
纯逻辑自检 30 项全过（secondsToMs 舍位 / resolveArrow 八方向 / resolveController 18 项组合）；
构建通过，产物含 loop-cards.js + .css，framework.css 已无该组件样式。

### 遗留观察（未改，供后续决定）
- 视口保留 `pointer-events: none`（卡片不拦截点击）；要卡片可点就删掉该样式
- 垂直轮播需调用方自行给容器限定高度，否则视口撑满全部卡片、不产生滚动

### 追加：loop-cards 回归修复（提交 `da06c1d`）

用户报告两个现象，**同源** —— 都是我上一轮把样式改为「组件按需注入」引入的：

1. **不自动轮播、要手动 resize 才动**：`ensureStyles()` 插入 `<link>` 是异步的，
   而测量在 rAF（约 16ms）后就跑。此时 CSS 未到 → 轨道还不是 flex 行、卡片纵向堆叠
   → `track.scrollWidth` 远小于实际 → 误判「内容不足一屏」→ 静态居中。
   resize 触发的重建那时样式早已就位，所以表现为「只有 resize 才滚」。
   → 修复：`stylesReady()` 返回 Promise（load/error 都 resolve），测量等
   `Promise.all([stylesReady(), document.fonts.ready])` 之后再 rAF。
2. **卡片上下边框不齐（不等高）**：等高原本靠 `align-items:center` + 卡片
   `min-height:100%`，这条链需要父级有确定高度（旧 `.loop-cards` 带 `height:max-content`）。
   插入「视口」层后视口高度变 `auto` → 百分比高度整条失效 → 卡片各按内容收缩。
   → 修复：改用 flex `align-items: stretch`，去掉失效的 `min-height` / `height`。

顺带：用 `ResizeObserver` 观察容器替代 window resize 监听 —— 覆盖不伴随窗口变化的
布局变动，也让「容器从 display:none 变可见」能自动恢复轮播（此前记为已知局限）；
重建后 400ms 内忽略回调以防自激。

**教训（已同步进 skill `frontend-monolith-esm-split`）**：把组件样式改成「按需注入」后，
异步到达的 CSS 会让所有基于尺寸的初始化判断失准 —— 测量必须挂在样式表 load 之后；
拆表时还要检查 `height:100%` / `min-height:100%` 这类依赖父级确定高度的链，
是否被新增的层级打断（症状：子项不再等高/不再撑满）。

验证：测量时机自检 13 项全过（就绪前不测量、不克隆、不渲染控制器；就绪后才克隆、
渲染控制器、启动 rAF、挂 ResizeObserver）。

### 追加：loop-cards 控制器交互修复（提交 `58c3bba`）

用户逐条反馈（多为前两轮遗留）：

1. **进度点没绑事件**（点不动）→ 点其他点调 `jumpTo(i)`（位移取与当前位置最近的
   等价位置，避免跨回绕边界时倒着滚一大段）；点当前那张的展开进度条 → `resetHold()`
2. **点暂停/播放把进度清零** —— 原 toggle 里 `holdStart = 0` 使恢复后从 0 重新计时。
   改为累积式：`holdElapsed` + 当前段；暂停 / 切后台先 `freezeHold()` 结算，恢复接着走
3. **椭圆条与按钮不等高** → 统一 `--loop-ctl-size`，椭圆补 `height` + `box-sizing`
4. **按钮没有明显点击效果** → 改用 Sober 的 `<s-icon-button>`（模板自带 `s-ripple`），
   图标颜色交给其主题变量自动适配亮 / 暗
5. **「激活过但已不是当前」的点残留填充**（与当前项混淆）→ `renderDots` 把非当前点的
   `--p` 归零，只留底色
6. 点的热区太小（0.45rem）→ `::before` 向外扩 0.35rem 透明热区

**查证方式（值得复用）**：`curl` 下载 `sober@1.0.6.min.js` 后用 node `slice` 提取组件定义，
确认 props / 模板 / `:host` 样式。正是这样发现 `s-ripple` 的 `attached` 模式
**触发函数由宿主组件调用**（单独放一个不会动），才确定该用自带 ripple 的 `s-icon-button`。

验证：控制器行为自检 15 项全过（部件结构、进度 0→0.5、**暂停恢复后进度 0.5 未清零**、
跳转位移 = -1×step、非当前点归零、点当前点重置）。
