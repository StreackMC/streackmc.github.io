# 2026-09-17 工作日志

## 移植旧站 pmd 的 Markdown 增强渲染（客户端 → 构建期）

用户后续要把文档站（PagesSober / pmd）迁过来，要求把旧站**客户端**的 Markdown 增强渲染
实现到当前 Astro 的**服务端（构建期）**渲染中。

### 旧站增强点（pmd.js + pmd-conf.js 中启用的）
- 目录 TOC（`index`）、标题锚点按钮（`hyper_markdown.header_link`）
- 外链箭头（`link.arrow`）、代码块复制按钮（`code`）
- 引用块提示框（`hyper_markdown.quotepro`）：`[i]` `[!]` `[！]` `[x]` `[@]` `[#hex$tip]`
- 图片查看器（`img.view`）

### 实现（构建期由 rehype 完成，仅交互留客户端）
- **新增 `src/plugins/rehype-doc.mjs`**：rehype 插件，产出增强标记
  - 标题：补 `id` + 追加 `.heading-anchor` 按钮（内联 SVG）
  - 外链：http(s) 且非站点 origin → `target/rel` + `.ext-link`
  - 代码块：`<pre>` 外包 `.code-block` 容器 + `.code-copy` 按钮
  - 引用块：解析提示标记 → `.doc-callout`（`--callout-color` 内联变量）+ `.doc-callout-title`（内联 SVG 图标）
  - 图片：`.doc-img` + `loading=lazy`
- `astro.config.mjs`：`markdown.rehypePlugins: [[rehypeDoc, { site }]]`
- `DocLayout.astro`：由 `render()` 的 `headings` 服务端生成 TOC；加图片灯箱 `<dialog>` + 引入 doc.js
- `[...slug].astro`：把 `headings` 传给 DocLayout
- **新增 `public/assets/code/doc.js`**：代码复制按钮、图片灯箱交互
- `doc.css`：新增锚点/外链箭头/复制按钮/callout/TOC/灯箱样式
- 示例：`markdown-syntax.md` 增加「提示框」演示段

### 关键坑（重要）
1. **Astro 的 `rehypeHeadingIds` 在用户 rehype 插件之后运行** →
   用户插件里标题尚无 `id`。解法：插件自行用 github-slugger 口径生成 id 并写入，
   Astro 之后会尊重已有 id，且其 `headings[].slug` 即取该 id → 目录链接与锚点天然一致。
2. **`firstTextNode` 会命中元素开头的空白文本节点** → blockquote 提示语法解析失败。
   解法：跳过纯空白文本节点。
3. **Astro 缓存配置里 import 的插件模块** → 改插件后必须清 `.astro` / `node_modules/.vite` 再构建，
   否则改动不生效（本次踩到）。

### 验证
- 构建通过，15 页；markdown-syntax 页：heading-anchor ×26、ext-link ×1、code-copy ×2、
  doc-callout-title ×5、doc-toc（2 层 10 项）、lightbox、doc-img 均产出
- TOC 链接 href 与标题 id 完全一致

## 同日追加：按反馈调整增强项

### 1. 移除图片查看器
- 删掉 `doc.js` 的灯箱逻辑、`DocLayout` 的 `<dialog>`、`doc.css` 的灯箱样式与 `img.doc-img{cursor}`
- 插件 `enhanceImage` 仅保留 `loading=lazy`/`decoding=async`（不再加 `.doc-img`）

### 2. `> [i]` “未渲染”问题 → 实为 Astro 内容缓存
- **根因**：Astro 内容层缓存（`node_modules/.astro` 数据存储）缓存了渲染结果；
  只改 rehype 插件、不改 .md 时缓存不失效 → dev/build 都沿用旧渲染
- 解法：`rm -rf .astro node_modules/.astro node_modules/.vite`，并新增 `npm run clean`
- 清缓存后 dev 与 build 均正常（callout ×5、heading-anchor ×14）

### 3. 链接语法糖（替代原先的“外链自动 target/箭头”）
- 规则改为：**默认链接当前窗口打开**；链接文字中写 `↗`/`$`/`฿` 时 → 移除标记、改新标签页 +
  `.ext-link`（CSS 箭头）。已带 `target=_blank` 的链接同样补箭头
- `enhanceLink` 重写；不再需要 `site` 选项（已从 astro.config 移除）

### 4. 任务列表换 Sober 组件
- `li.task-list-item` 内的 `<input type=checkbox>` → `<s-checkbox disabled [checked]>`
  （Sober 属性：`checked`/`indeterminate`/`disabled`，默认插槽为标签文本；v1 文档备份
  https://kdxiaoyi.top/SoberDoc/#s-checkbox）
- `doc.css` 对应样式由 `input` 改为 `s-checkbox`

### 5. Astro 特性 × Markdown 集成（研究 + 落地）
- 站点布局靠 Astro 插槽（`toolbar-nav`/`notes`/`dialogs`/`scripts`/`head`），Markdown 无法直接用插槽
- **落地**：frontmatter `nav: [{ label, href?, cmd? }]` → `DocLayout` 渲染为
  `<template slot="toolbar-nav" data-toolbar-nav>`，`href` 走 `url:` 命令、`cmd` 走任意 `data-cmd`
  （`content.config.ts` schema 已加 `nav`；`[...slug].astro` 透传）
- **备选（已验证可行）**：在 Markdown 里直接写原始 HTML `<template data-toolbar-nav>…</template>`
  —— 会被保留（包在 `<p>` 内但无碍），framework.js 扫描整页即可生效
- 其他可集成点：`markdown.components` 覆盖元素渲染；`head`/`scripts` 可用 frontmatter 注入


## 同日追加 2：目录开关/折叠 + 标题整块可点
- **标题整块可点**：`enhanceHeading` 改为把标题全部内容包进 `<a class="heading-link" href="#id">`（文字+图标整块可点，对应旧站）；
  若标题内已含 `<a>`（避免锚点嵌套）则回退为“仅图标可点”（`.heading-anchor`）
- **目录开关**：`DocLayout` 的目录头部加 `<s-switch data-doc-toc-switch checked>`（Sober 组件，默认开）
- **自动折叠**：`doc.js` 的 `initToc()` 在加载时一次性判定 `.doc-toc-list` 高度 ≥ `0.4×innerHeight`（40dvh）则默认折叠；
  开关 `change` 切换 `.doc-toc-collapsed`（隐藏列表）
- 相关 CSS：`.heading-link`/`.heading-anchor-icon`、`.doc-toc-head`/`.doc-toc-switch`/`.doc-toc-collapsed`
