### 关键技术决策
- **Astro slot 属性冲突**：HTML `slot="0"` 属性被 Astro 误解为插槽指令，用 `<div style="display:contents">` 包裹层隔离
- **is:inline 指令**：所有引用 public/ 资源或外部 URL 的 `<script>` 标签必须加 `is:inline`，否则 Astro 尝试打包导致构建失败
- **遥测禁用**：构建时需设置 `ASTRO_TELEMETRY_DISABLED=1` 环境变量（沙箱环境无法写入 ~/Library/Preferences/astro）

## 布局崩溃修复

用户反馈"页面正文布局崩溃了"，诊断并修复两个问题：

### 问题 1：元素落入默认插槽
`<template data-toolbar-nav>`、`<template data-inject="notes">`、`<s-bottom-sheet>`、`<s-dialog>` 缺少 Astro `slot` 属性，全部掉进默认插槽，被塞进 `.contents` / `s-scroll-view` 内部。
**修复**：添加 `slot="toolbar-nav"`、`slot="notes"`、`slot="dialogs"` 路由到正确位置。

### 问题 2：Astro 对自定义元素保留 slot 属性
Astro 对自定义元素（`s-bottom-sheet`、`s-dialog`）**不消费** `slot` 属性——输出 HTML 中保留了 `slot="dialogs"`，导致浏览器尝试将组件插入 `s-page` 的 Shadow DOM "dialogs" 槽位，但 `s-page` 没有此槽位，组件不渲染。
**修复**：用 `<Fragment slot="dialogs">` 包裹自定义元素，让 Astro 在 Fragment 上消费 `slot` 属性，内部元素保持干净。
- 注意：`<template>` 元素的 `slot` 属性会被 Astro 正常消费，无需 Fragment 包裹
- 注意：`s-tooltip slot="action"` 是 Sober UI 的 Shadow DOM 槽位，保留是正确的
