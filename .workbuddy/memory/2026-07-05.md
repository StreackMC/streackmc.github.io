### 关键技术决策
- **Astro slot 属性冲突**：HTML `slot="0"` 属性被 Astro 误解为插槽指令，用 `<div style="display:contents">` 包裹层隔离
- **is:inline 指令**：所有引用 public/ 资源或外部 URL 的 `<script>` 标签必须加 `is:inline`，否则 Astro 尝试打包导致构建失败
- **遥测禁用**：构建时需设置 `ASTRO_TELEMETRY_DISABLED=1` 环境变量（沙箱环境无法写入 ~/Library/Preferences/astro）

## 布局崩溃修复

用户反馈"页面正文布局崩溃了"，诊断并修复两个问题：

### 问题 1：元素落入默认插槽
`<template data-toolbar-nav>`、`<template data-inject="notes">`、`<s-bottom-sheet>`、`<s-dialog>` 缺少 Astro `slot` 属性，全部掉进默认插槽，被塞进 `.contents` / `s-scroll-view` 内部。
**修复**：添加 `slot="toolbar-nav"`、`slot="notes"`、`slot="dialogs"` 路由到正确位置。

### 问题 2：Astro 对自定义元素保留 slot 属性
Astro 对自定义元素（`s-bottom-sheet`、`s-dialog`）**不消费** `slot` 属性——输出 HTML 中保留了 `slot="dialogs"`，导致浏览器尝试将组件插入 `s-page` 的 Shadow DOM "dialogs" 槽位，但 `s-page` 没有此槽位，组件不渲染。
**修复**：用 `<Fragment slot="dialogs">` 包裹自定义元素，让 Astro 在 Fragment 上消费 `slot` 属性，内部元素保持干净。
- 注意：`<template>` 元素的 `slot` 属性会被 Astro 正常消费，无需 Fragment 包裹
- 注意：`s-tooltip slot="action"` 是 Sober UI 的 Shadow DOM 槽位，保留是正确的

## 第二轮布局修复（用户反馈三个问题）

### 问题 1：framework.css 直接子选择器失效
`.contents > .content` 使用 `>` 直接子选择器，但 `display:contents` 包裹层（必需，防止 Astro 解释 `slot="0"` 为插槽指令）使 `.content` 不再是 `.contents` 的直接子元素。导致 `position:relative`、高度、网格布局全部失效，`.main` 无法撑开滚动。
**修复**：将 3 处 `.contents > .content` 改为后代选择器 `.contents .content`。

### 问题 2：webtool/* 不应迁移为 Astro 组件
webtool 页面仅使用 SoberJS，不使用 Streack Website Framework。错误地套了 ToolLayout + Sidebar 导致页面完全损毁。

## 安装 astro-link + astro-spa + VSCode 配置更新

### 安装内容
- **astro-link**：智能 `<Link>` 组件，自动处理外链 rel/target、mailto/tel 混淆、内链 prefetch 标记
- **astro-spa**：客户端 SPA 导航（预取、缓存、进度条、淡入动画，~1.3KB gzipped）
- `<Spa />` 组件添加到 FrameworkLayout，所有 Astro 页面获得 SPA 行为

### SPA 隔离机制
webtool 旧框架页面天然不受 SPA 影响：
1. webtool 页面本身不含 `<Spa />` 组件（静态透传，Astro 不加工）
2. 工具栏导航用 `onclick`（非 `<a>` 标签），astro-spa 只拦截 `document.links`
3. 页脚 webtool 链接用 `target="_blank"`，astro-spa scan 过滤排除

### astro-spa ignores prop bug
`ignores` prop 有 bug：scan.js 在 `ignores.length > 0` 时生成 `ignores.includes(link.href)` 代码，但 `ignores` 变量在运行时未定义，导致 ReferenceError 完全破坏 SPA。**不可使用 ignores prop。**

### VSCode 配置
- `launch.json`：添加 `preLaunchTask: "Execute Astro Server"`，启动浏览器调试时自动启动 Astro dev server
- `tasks.json`：`npx astro dev` 添加 `--host` 标志
