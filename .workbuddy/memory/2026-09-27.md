# 2026-09-27

## toolbar1 插槽搬进移动端抽屉后 data-cmd 失效（提交 `5d9b8ac`）

**现象**：带 `data-cmd` 的 toolbar1 插槽导航项，在移动端折叠菜单里点不动。

**根因（两件事叠加，缺一不可）**：
1. `bindCommandOn` 旧写法在绑定时 `delete ele.dataset.cmd` —— 把属性当成「已绑定」标记删掉。
   而 `cloneNode` **只复制属性、不复制事件监听**，于是克隆件既没属性也没监听 = 死元素。
2. `initToolbar2Slots` 打开抽屉时克隆导航项，但克隆后没有补绑。

**改法**：
- `commands.js`：改用 `WeakSet` 记「已绑定」，**保留属性** → 幂等且克隆件可再绑
- `toolbar.js`：抽屉克隆后 `bindCommandOn(navSlot)`；`registerToolbarSlot` 注入时就地绑定
- `loop-cards.js`：三段式轨道的克隆卡片一并补绑（使克隆件与原件命令行为一致）

**审计结论**：全仓库 `cloneNode` 仅 3 处 —— toolbar 抽屉（本次修复）、loop-cards 轨道（一并补绑）、
其余 DOM 注入点（popups 等）不含命令。

**验证手法（值得复用）**：DOM stub 自检 21 项 + **反证** —— 把旧的破坏性写法临时放回
（用 `cp` 备份 → `sed`/Edit 插桩 → 跑测试应失败 → `cp` 还原 + `cmp` 校验字节一致 → 复跑应全绿）。
反证让「这套断言真能抓到该 bug」成为可验证事实，而不是自我感觉。
本次反证时第一次插桩位置错了（插在取参数之前，把参数也弄丢了，失败项数偏多），
改成**忠实还原旧代码整段**后才得到可信的对照结果。

## 教训

1. 「绑定后删属性」看似能防止重复绑定，代价是属性再也无法作为克隆的载体 ——
   用 WeakSet 这类**外部标记**代替 DOM 上的自毁式标记。
2. 只要代码里有 `cloneNode`/`innerHTML` 注入，就要问一句「这里的事件绑定谁来补」。
