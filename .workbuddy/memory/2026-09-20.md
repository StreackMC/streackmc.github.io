## 新增「注释合并」语法糖（构建期 rehype 实现）

需求：注释应统一渲染到页脚注释区，而 Markdown 有两种注释写法 —— `[^n]:` 脚注、文末列表，
两者都要搬进页脚。

### 已有基础设施（无需改框架！）
- `Footer.astro`：`#footer-notes-slot > ol#notes`
- `framework.js` 步骤 4b：把任意 `<template data-inject="notes">` 的 innerHTML 注入 `ol#notes`，并移除模板
- `framework.js` 步骤 11：`sup[data-note=token]` ↔ `li[data-note=token]` 绑定
  （按 li 位置自动编号、点击互跳、给条目补 `↩` 返回链接）
→ 结论：插件只需在构建期产出这两种标记即可，**不需要动 framework/Layout**。

### 语法（两种，可混用）
- A. `[^1]: 说明` 标准脚注（remark-gfm）：插件把文末 `<section data-footnotes>` 拆成
  `li[data-note="<label>"]`，正文的 `<sup><a data-footnote-ref>` 改写成 `<sup data-note="<label>"></sup>`
- B. 单独一行 `<!-- notes -->` + 紧随其后（中间只隔空白）的 ul/ol：列表整体搬入页脚，
  条目 token 为 `notes-1`、`notes-2`…；正文若需引用，手写 `<sup data-note="notes-2"></sup>`
- 编号顺序：脚注在前（按定义顺序），标记列表在后 —— 页脚按 li 位置编号，故顺序即显示序号

### 为什么必须「显式标记」而非自动判定
全量扫描 46 篇内容，**17 篇的末尾块就是列表**，且绝大多数是正文：
`event/*` 的「注意事项」、`doc/updata/*` 的更新日志（末项形如 `* 新增`）、`rule.md` 的定义条目……
无条件搬运会把这些正文搬进页脚。已就此与用户确认，采用 `<!-- notes -->` 显式标记。

### 踩到的坑（都很隐蔽，已写入 MEMORY.md）
1. **不能用 hast 的 `content` 构建 `<template>`**：Astro 在用户 rehype 插件之后还跑 `rehype-raw`，
   而 `hast-util-to-html` 对 template 只序列化 `node.content`，rehype-raw 的「序列化→重解析」
   往返会把 content 清空 → 产物成了空 `<template></template>`（实测）。
   **解法**：整段模板用 **raw 字符串节点**承载，交给 rehype-raw 自己解析；
   条目用 `toHtml(li)` 序列化（为此把 `hast-util-to-html` 加进 devDependencies）
2. **`dataFootnoteBackref` 的值是空字符串 `""`**（而 `dataFootnoteRef` 是 `true`，两者不对称）
   → 用真值判断会漏掉 ↩，必须用 `!== undefined`
3. `<!-- notes -->` 在用户插件阶段是 **raw 节点**（不是 comment 节点）；标记与列表之间夹着一个
   纯空白 text 节点，找「下一个兄弟元素」时要跳过空白
4. 顺序也要注意：先跑通用 `transform()`（让注释里的链接语法糖/代码块也享受增强），再 `extractNotes()`

### 修复：注释条目里的 ↩ 被换行
- 症状：页脚注释条目末尾的 `↩`（框架 append 的返回链接）被挤到下一行，即使空间充足。
- 原因：`[^n]:` 脚注的条目是 `<li><p>…</p></li>` —— **`<p>` 是块级元素**，
  而框架是把 `<a>↩</a>` append 到 `<li>` 末尾的，前面有个块级元素就必然换行。
  页脚注释区（`ol#notes`）**没有任何 CSS**（全仓 grep 无相关规则），所以这是纯结构问题。
  站内既有注释（`index.astro`、`temple/*`）写的都是**行内文本**，与之一致才是正解。
- 修法：插件新增 `unwrapParagraphs(li)`，抽出条目时把 `<p>` 展开为行内内容；
  多段之间补一个 `<br>`，既保留断行又让 ↩ 跟在末段同行。两种注释写法都套用。
- 验证：单段 / 多段 / 富文本脚注、松列表四种情况产出的 `<li>` 均为行内；
  真实页面 `donate`、`backup_and_restore`、`entroprix`、`markdown-syntax` 的
  `<li><p>` 出现次数为 0。
- 已知边界：若条目里含**嵌套列表**（`<ul>` 等块级子元素），↩ 仍会另起一行
  —— 属罕见情况，未处理。

## 修复：`/about/legal` 标题里的 s-icon 不渲染

- 症状：`about/legal/index.astro` 把图标直接内联进 `config.title`
  （`` const icon = `<s-icon style="width: 1em;"><svg …></svg></s-icon>` `` → `` title: `${icon}法律信息` ``），
  页面里却看不到图标。
- 原因：`SelectorLayout.astro` 用 `{config.title}` 输出，而 **Astro 的文本插值默认 HTML 转义**
  → `<s-icon …>` 变成 `&lt;s-icon …&gt;`，即以源码文本显示；而同一份值写进
  `[data-selector-config]` 时走 `set:html={JSON.stringify(config)}`（不转义），两边不一致。
- 修法：`SelectorLayout` 改为 `set:html={config.title}` / `set:html={config.description}`
  （description 为空时不再输出空的 `<p>`）。
- 顺带修一处潜在同类问题：`selector.js` 的层标题原为 `heading.textContent = layerTitle`，
  而 layerTitle 会 fallback 到 `config.title` / `option.label`，二者都可能含 HTML
  （`option.label` 本就用 innerHTML 注入）→ 改为 `innerHTML`；否则没写 layerTitle 的页面
  会把 `<s-icon …>` 当纯文本显示。
- 核对：`s-icon`（sober@1.0.6）模板就是 `<slot></slot>`，并带 `::slotted(*){width/height:100%}`
  → 自定义 SVG 走插槽可正常渲染，不必用 `name=`。

## 同日追加：修正「重新选择」/ 面包屑回退不再滚动（上次修复的回归）
- 症状：上一轮为「初始化不滚动」加 `if (depth > 0)` 守卫后，点「重新选择」不再滚动，
  用户停在结果卡被清空后的空白位置；面包屑回到根层同样不滚。
- 根因：用 **depth 推断「是否初始化」不可靠** —— 第 0 层既可能是初始化渲染，
  也可能是用户主动的重新选择 / 面包屑回退，一刀切会连后者一起掐掉。
- 修法：`renderLayer` 加第 4 参 `autoScroll`（undefined → 缺省按 `depth > 0` 推断）：
  - `resetSelector()` 与 `goBackTo()` 两处 → 显式 `true`
  - `selectPath` 的根层与 `initInstance` 启动渲染 → 显式 `false`
  - 下钻分支不变（缺省推断即可）
- 验证：写了临时自检脚本（`.selcheck.tmp.mjs`，用毕已删），基于 **node-html-parser 搭最小 DOM 壳**，
  记录每次 `scrollIntoView`。7 个场景 14 项断言全过：
  初始化 0 次滚动 / 下钻 depth1、depth2 各滚 1 次 / 面包屑回根滚 depth0 /
  结果卡滚到 start / **点「重新选择」滚 depth0 且结果卡清空** / 带 `?selector` 时根层不滚、深层滚。
  **反向验证**：把显式 `true` 去掉再跑 → D、F 两项失败（0 次滚动），证明该自检能真正抓到此回归。
- 搭壳时踩的两个坑（都是 node-html-parser 与浏览器的差异，非产品 bug）：
  1. 它的 `classList` 在构造时快照 class 属性，之后 `setAttribute('class', …)` 改的 class 不会同步进去，
     下一次 `classList.add()` 会把新 class **抹掉** → 需让 `setAttribute('class')` 同步刷新其内部 Set；
  2. `innerHTML = ''` 会残留一个空 TextNode，断言应看 `innerHTML.trim() === ''` 而非 `childNodes.length`。
- 现存遗留：`public/webtool/code/javascript/selector.js` 仍是初版 webtool 版（含自己的
  `scrollIntoView`），**无任何引用**，属死文件。本次未动。
