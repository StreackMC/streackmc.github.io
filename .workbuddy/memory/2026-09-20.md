## 为 Markdown 增加「是否渲染页首目录」标志（frontmatter `toc`）

用户澄清：此前「目录加一个开关控制是否使用」指的是**在 Markdown 里用标志控制该页要不要目录**，
而不是运行时 UI 控件（上一轮误做成了 s-switch → 已改为旋转箭头）。

实现（3 处 + 1 处文档）：
- `src/content.config.ts`：schema 新增 `toc: z.boolean().optional()`（缺省渲染）
- `src/pages/[...slug].astro`：`<DocLayout toc={data.toc !== false} … />`
- `src/layouts/DocLayout.astro`：新增 `toc?: boolean` prop（默认 true）；
  渲染条件由 `{tocHtml && (…)}` 改为 `{toc && tocHtml && (…)}`
- `src/content/_md/index.md`：在「Frontmatter（可选）」里补 `toc: false` 示例与说明

行为：`toc: false` 时该页**完全不输出目录区块**（DOM 里没有 `.doc-toc`，
而非仅 `display:none`）——视觉等价且不浪费 DOM。写作 `toc: false` 才生效，
省略或 `true` 均渲染；`buildToc` 仍保留「少于 2 个 h2/h3 不渲染」的原逻辑。

验证：临时给 `_md/guide/markdown-syntax.md` 加 `toc: false` → build 后该页
`doc-toc` 计数 0；对照页（`/_md/`、`/_md/guide/`）`doc-toc-head` 计数 1；
随后已还原样本。构建 57 页通过。

## 新增「注释合并」语法糖（构建期 rehype 实现）

需求：注释应统一渲染到页脚注释区，而 Markdown 有两种注释写法 —— `[^n]:` 脚注、文末列表，
两者都要搬进页脚。

### 已有基础设施（无需改框架！）
- `Footer.astro`：`#footer-notes-slot > ol#notes`
- `framework.js` 步骤 4b：把任意 `<template data-inject="notes">` 的 innerHTML 注入 `ol#notes`，并移除模板
- `framework.js` 步骤 11：`sup[data-note=token]` ↔ `li[data-note=token]` 绑定
  （按 li 位置自动编号、点击互跳、给条目补 `↩` 返回链接）
→ 结论：插件只需在构建期产出这两种标记即可，**不需要动 framework/Layout**。

### 语法（两种，可混用）
- A. `[^1]: 说明` 标准脚注（remark-gfm）：插件把文末 `<section data-footnotes>` 拆成
  `li[data-note="<label>"]`，正文的 `<sup><a data-footnote-ref>` 改写成 `<sup data-note="<label>"></sup>`
- B. 单独一行 `<!-- notes -->` + 紧随其后（中间只隔空白）的 ul/ol：列表整体搬入页脚，
  条目 token 为 `notes-1`、`notes-2`…；正文若需引用，手写 `<sup data-note="notes-2"></sup>`
- 编号顺序：脚注在前（按定义顺序），标记列表在后 —— 页脚按 li 位置编号，故顺序即显示序号

### 为什么必须「显式标记」而非自动判定
全量扫描 46 篇内容，**17 篇的末尾块就是列表**，且绝大多数是正文：
`event/*` 的「注意事项」、`doc/updata/*` 的更新日志（末项形如 `* 新增`）、`rule.md` 的定义条目……
无条件搬运会把这些正文搬进页脚。已就此与用户确认，采用 `<!-- notes -->` 显式标记。

### 踩到的坑（都很隐蔽，已写入 MEMORY.md）
1. **不能用 hast 的 `content` 构建 `<template>`**：Astro 在用户 rehype 插件之后还跑 `rehype-raw`，
   而 `hast-util-to-html` 对 template 只序列化 `node.content`，rehype-raw 的「序列化→重解析」
   往返会把 content 清空 → 产物成了空 `<template></template>`（实测）。
   **解法**：整段模板用 **raw 字符串节点**承载，交给 rehype-raw 自己解析；
   条目用 `toHtml(li)` 序列化（为此把 `hast-util-to-html` 加进 devDependencies）
2. **`dataFootnoteBackref` 的值是空字符串 `""`**（而 `dataFootnoteRef` 是 `true`，两者不对称）
   → 用真值判断会漏掉 ↩，必须用 `!== undefined`
3. `<!-- notes -->` 在用户插件阶段是 **raw 节点**（不是 comment 节点）；标记与列表之间夹着一个
   纯空白 text 节点，找「下一个兄弟元素」时要跳过空白
4. 顺序也要注意：先跑通用 `transform()`（让注释里的链接语法糖/代码块也享受增强），再 `extractNotes()`
